# Руководство пользователя LGV

LGV (Lavrov Genome Viewer) показывает выравнивания ридов (BAM, CRAM) на референсном
геноме — для медицинской генетики и генетики человека. Работает в браузере из одного файла
`lgv.html`, без установки и без сервера: файлы читаются по частям прямо с диска или по ссылкам,
которые вы дали, и никуда не загружаются.

Руководство описывает LGV в текущем виде и дополняется с каждым обновлением. Английская версия:
[USER_GUIDE.md](USER_GUIDE.md).

## 1. Запуск

Откройте `lgv.html` в Chrome, Edge, Firefox или Safari (лучше Chrome или Edge: часть возможностей
есть только в них, см. 3.1). При запуске LGV загружает референс **GRCh38 / hg38** (только
последовательность, из открытого хранилища команды IGV) и открывается на BRCA1. Короткое сообщение
подтверждает загрузку.

- Что открывать при запуске, задаётся в **Вид → При запуске открывать**: GRCh38, GRCh37, T2T-CHM13,
  демо-данные или ничего.
- Без интернета референс не загрузится; тогда LGV открывает встроенные демо-данные (синтетический
  контиг `demo` с примерами вариантов) и сообщает об этом.
- Интерфейс на английском; русский — в **View → Language**.

## 2. Экран

Сверху вниз:

- **Верхняя панель**: **LGV** (клик — «О программе»: версия, авторство, сторонний код и данные,
  журнал диагностики), **список контигов** (выбор хромосомы или контига показывает её целиком;
  сначала хромосомы, альтернативные и неразмещённые контиги — в **Другие контиги**), поле локуса с
  **Go**, **← →** (назад / вперёд), **− +** (масштаб), **PNG** (сохранить картинку) и
  **Ссылка** (скопировать ссылку на этот вид) — раздел 15a, ширина окна, загруженный референс и
  образцы, строка состояния (сколько ридов, время загрузки и отрисовки), **Open** и **View**. **H**
  прячет панель; кнопка в углу возвращает её.
- **Карта хромосомы**: хромосома на экране, красная рамка — где окно (раздел 6).
- **Заголовки окон**: только когда регионов несколько (раздел 5).
- **Линейка** и **референсная последовательность**: координаты с 1. Референс —
  цветные блоки, при сильном приближении — буквы.
- **Дорожка генов**: транскрипты MANE (раздел 7).
- **Образцы**: у каждого покрытие и риды. Небольшая подпись вверху ридов, даже когда образец
  один, называет его (файл и образец; может закрывать ряд-другой), справа — × для закрытия.

Интерфейс специально компактный: как можно больше экрана отдаётся данным. Пояснения убраны во
**всплывающие подсказки**: задержите указатель на кнопке, настройке, строке карточки, карте
хромосомы, линейке, дорожке генов или покрытии — через мгновение появится короткое пояснение
(обычная подсказка браузера: она не всплывает, пока указатель движется, и над ридами её нет).

## 3. Открытие данных

Нажмите **Open**.

### 3.1 С диска

- **Выбрать файлы**: один или несколько `.bam` / `.cram`. Каждый сопоставляется с индексом по имени:
  `sample.bam.bai` или `sample.bai`, `sample.cram.crai` или `sample.crai` (регистр не важен). Вместе
  с ними можно выбрать референс (`.fa` / `.fasta` / `.fna`, можно `.gz`, с `.fai` и `.gzi`).
- **Только .bam или .cram, без индекса** (Chrome, Edge): веб-страница может читать только выбранные
  вами файлы, поэтому LGV один раз спрашивает — **Разрешить папку**. Окно выбора папки открывается
  там, где лежит файл; подтвердите — и LGV сам возьмёт индекс оттуда. Следующие файлы из этой же
  папки открываются без вопроса, пока страница открыта. Доступ только на чтение и нигде не
  сохраняется. В Firefox и Safari так нельзя: выберите файл вместе с индексом или всю папку.
- **Выбрать папку**: LGV найдёт в ней все образцы с индексами. Если образцов несколько, сначала
  покажет список (первые четыре отмечены).
- **Перетащить** файлы или папку на экран — то же самое.

В Chrome и Edge любое окно выбора файлов и папок открывается в папке, с которой работали последней
(пока страница открыта): данные обычно лежат в одном месте.

Повторное открытие того же файла ничего не делает: он уже открыт.

### 3.2 По ссылке

Вставьте одну или несколько HTTPS-ссылок на BAM или CRAM, по одной в строке. Индекс ищется рядом
с каждым файлом (`.bam.bai`, затем `.bai`; `.cram.crai`, затем `.crai`), если не указан явно.
Сервер должен разрешать CORS и Range-запросы (обычное дело для облачных бакетов с подписанными
ссылками). Для серверов, которым нужен токен доступа, его можно указать; он не сохраняется.

### 3.3 Референс

Референс задаёт геном. Загрузка другого референса переключает геном и закрывает
открытые образцы.

- **Готовые**: GRCh38, GRCh37 и T2T-CHM13 v2.0 (открытые копии от команды IGV).
- **Свой**: FASTA с диска или по ссылке. Без `.fai` LGV индексирует файл в браузере за один проход
  (обычный, bgzip или gzip; виден прогресс). С `.fai` (и `.gzi` для bgzip) открывается сразу.
- Образцы сопоставляются с референсом по имени контига (без учёта регистра, префикса `chr` и номера
  версии), затем по длине, которая есть только у одного контига с каждой стороны. Образец,
  выровненный на другую сборку (большой контиг с тем же именем и другой длиной, например chr1 из
  GRCh37 против GRCh38), LGV не открывает и объясняет почему: координаты были бы неверными.
- Без референса координаты берутся из заголовка первого образца, а референсные основания
  восстанавливаются из тегов MD там, где есть риды.
- **CRAM** хранит риды как отличия от референса, с которым был создан. LGV сверяет каждую часть
  файла с загруженным референсом (MD5) и не показывает риды, собранные на другом референсе, —
  вместо того чтобы показать неверные основания.

## 4. Перемещение

- **Поле локуса**: введите `chr7:117,559,500-117,560,000`, `chr7:117559590` (окно 100 п.н. вокруг
  позиции), имя контига (`chrX`, `X` и `x` — одно и то же), **символ гена** (`CFTR`) или транскрипт
  MANE (`NM_000492`, `ENST00000003084`, с версией или без). Enter или **Go**. При вводе гена
  появляются подсказки. `500-100` читается как `100-500`; позиции за концом контига переносятся на
  его конец.
- **Несколько локусов или генов через пробел** открываются рядом (раздел 5).
- **Перетаскивание** ридов влево-вправо — движение по геному.
- **Масштаб**: кнопки **− +** и клавиши (сразу во всех окнах), Ctrl + колесо или щипок на тачпаде,
  двойной клик (приблизить в этой точке).
- **Протянуть по линейке** — приблизить выделенный участок; клик по линейке центрирует там.
- Кнопки **← →**: назад и вперёд по местам, куда вы переходили, — введённые локусы и гены,
  примеры, «к мейту», «мейт в соседнем окне», «показать весь ген», клики по карте хромосомы.
  Сдвиг и масштаб отдельными шагами не считаются. «Назад» после нескольких регионов рядом
  возвращает их все.

## 5. Несколько регионов рядом

Экран делится на окна:

- **Правый клик по риду → Показать регион мейта в соседнем окне** (или кнопка в карточке рида)
  открывает окно рядом с текущим, по центру — мейт, в том же масштабе. Рид и мейт обведены во всех
  окнах, а новое окно прокручено так, чтобы мейт был виден.
- **Несколько локусов или генов в поле адреса** (через пробел) — по окну на каждый; один локус
  возвращает одно окно.
- У каждого окна своя линейка, масштаб, загруженный участок, раскладка ридов и прокрутка. В
  заголовке — номер и локус; активное окно (последнее, по которому кликнули) подчёркнуто, клавиши
  действуют на него.
- **×** в заголовке окна закрывает его.
- Минимум 6 окон всегда, больше — насколько позволяет ширина (около 60 пикселей на окно).

## 6. Карта хромосомы

Полоса наверху показывает хромосому на экране: для GRCh38 — с полосами окраски (тёмные —
G-позитивные, красная — центромера) и названиями полос (p21.3, q11.21…) внутри тех полос, где
они помещаются; для других геномов — простая полоса. **Красная рамка** — где
окно; рамка активного окна залита. При нескольких окнах рамки пронумерованы как заголовки окон, а
окна на разных хромосомах дают несколько карт рядом. **Клик или перетаскивание** по карте переносит
туда активное окно.

## 7. Гены (MANE)

Под референсом — дорожка генов: транскрипты MANE Select и MANE Plus Clinical на GRCh38 (19 373
транскриптов, MANE v1.5), встроенные в LGV: работают без сети, и введённые названия генов никуда не
отправляются.

- Толстые блоки — кодирующие экзоны, тонкие — UTR, линия со стрелками — интрон и цепь. Plus
  Clinical — своим цветом. При приближении внутри экзонов видны номера (`экз10`), по направлению
  транскрипта.
- **Клик по транскрипту**: ген и HGNC, полное название, статус MANE, Ensembl и RefSeq, границы гена
  (цепь +/−), число экзонов, кодирующая часть и куда попадает точка клика: `экзон 11 из 27`,
  `(UTR)` или `интрон 3 из 26`. **Показать весь ген** приближает к нему; **Copy** копирует текст.
- Дорожка видна, только если координаты — GRCh38; выключается в **Вид**.

## 7a. Свои дорожки: BED, bedGraph, VCF, GTF, GFF3

Файлы аннотаций открываются так же, как образцы, — **Open → С диска** (выбрать, перетащить или
вместе с образцами) или **По ссылке** — и распознаются по имени: `.bed` (а также `.narrowPeak`,
`.broadPeak`), `.bedgraph` / `.bg`, `.vcf`, `.gtf`, `.gff` / `.gff3`, каждый также как `.gz` (gzip
или bgzip). Индекс не нужен: файл читается целиком (до 512 МБ в распакованном виде).

Дорожки появляются полосами под дорожкой генов, в порядке открытия, и не прокручиваются вместе с
образцами. Каждая начинается тонкой строкой с именем файла, × справа закрывает дорожку. Имена
контигов совпадают с `chr` и без.

- **BED** (от 3 до 12 колонок): объекты в два ряда с именами; блоки рисуются как экзоны, толстая
  часть — как кодирующая, цепь — стрелками (или заострённым концом), `itemRgb` задаёт цвет.
- **GTF / GFF3**: экзоны и CDS собираются в транскрипты (по `transcript_id` или `Parent`) и рисуются
  как дорожка генов; строки без экзонов (повторы, регионы) — как есть.
- **bedGraph**: столбчатая диаграмма; шкала (наибольшее видимое значение, `±` при отрицательных) — в
  строке имени.
- **VCF**: отметка на каждый вариант (красная; серая, если FILTER не PASS), под ней — ряд на каждый
  образец, до 8 образцов, с его именем: светло-серый — гомозигота по референсу, синий —
  гетерозигота, бирюзовый — гомозигота по альтернативному аллелю, только контур — нет генотипа. Если
  образцов больше, строка имени говорит, сколько их.
- **Клик по объекту** — карточка: в верхней строке позиция и цепь, Copy и ×; ниже имя дорожки и
  подробности — для BED имя, score, блоки и толстая часть; для GTF / GFF3 тип и все атрибуты; для
  bedGraph значение; для VCF ID, REF, ALT, QUAL, FILTER, все поля INFO и поля FORMAT каждого образца
  (до 30 образцов).
- Строки, которые не удалось прочитать, пропускаются и считаются: сообщение скажет сколько. Если не
  прочитано большинство строк, файл, скорее всего, не того формата, что значится в имени (например,
  таблица `samtools idxstats`, сохранённая как `.bed`): сообщение говорит об этом и показывает первую
  такую строку.
- При загрузке другого референса дорожки остаются открытыми (это позиции, а не риды).

**Переключатели типов дорожек.** Когда открыта хотя бы одна дорожка аннотаций, в верхней панели есть
переключатель на каждый тип — `✓ BAM 3`, `✓ VCF`, `✓ BED`, `✓ GFF`, `✓ bedGraph`, `✓ TDF`,
`✓ bigWig` (BAM включает CRAM; число — сколько их). Клик скрывает все дорожки этого типа во всех
окнах, повторный клик возвращает их как были. При выключенном BAM риды и покрытие не читаются вовсе,
поэтому целая хромосома открывается сразу, и на этом масштабе можно смотреть остальные дорожки —
например, BED с регионами потери гетерозиготности. Открытие нового образца снова включает BAM.
Переключатели действуют, пока страница открыта.

## 7b. Дорожки значений: TDF и bigWig

Файлы значений вдоль генома — покрытие, аллельные доли, оценки — открываются так же, как другие
дорожки (**Open → С диска** или **По ссылке**), по имени: `.tdf` (их делает igvtools) и `.bw` /
`.bigwig`. Целиком они не читаются: читается только та часть файла, которая нужна для текущего
вида, поэтому файл любого размера открывается сразу. По ссылке сервер должен поддерживать запросы
Range.

**Несколько дорожек в одном файле** (в TDF их может быть несколько, например по одной на образец)
показываются отдельными рядами, у каждого имя слева вверху; до 40 рядов, если их больше, это
сказано в строке имени.

**Что читается для вида.** В обоих форматах хранятся сами значения и заранее посчитанные сводки
для более крупных масштабов. Вблизи LGV рисует сами значения. При отдалении он читает сами значения,
пока для вида их нужно не больше 16 МБ (4 МБ по ссылке); дальше берёт сводки, и строка имени говорит
об этом: например, `среднее по окнам 114 kb`. В файле могут быть сводки только для самых крупных
масштабов (igvtools можно велеть остановиться раньше); тогда между ними и самими значениями берутся
самые подробные из имеющихся сводок. Если в файле нет сводки нужного вида (TDF сделан
только со средним, а выбран максимум), строка имени называет то, что показано вместо него. Если не
подходит ни то, ни другое, в строке написано `приблизьте`.

**Как рисуется дорожка.** Настройки TDF берутся из его строки трека (строки `track ...` того
wiggle или bedGraph, из которого он сделан; у bigWig её нет). Выполняются все настройки строки
трека UCSC для wiggle:

| Настройка | Что значит | Если в файле нет |
| --- | --- | --- |
| `graphType=bar\|points` | столбики или точки (читаются также `line` и `heatmap`) | см. ниже |
| `windowingFunction=maximum\|mean\|minimum\|mean+whiskers` | какое значение показывает столбец экрана, если в него попало несколько | maximum |
| `autoScale=on\|off`, `viewLimits=lo:hi` | шкала по видимым значениям или постоянная | авто |
| `alwaysZero=on` | автоматическая шкала всегда включает 0 | нет |
| `transformFunc=LOG` | логарифмическая шкала: ln(1 + x), ниже нуля −ln(1 − x) | нет |
| `smoothingWindow=2…16` | скользящее среднее по стольким столбцам экрана | нет |
| `yLineMark=v`, `yLineOnOff=on` | пунктир на уровне v | нет |
| `color=r,g,b`, `altColor=r,g,b` | цвет значений ≥ 0 и отрицательных | цвета темы |
| `maxHeightPixels=max:default:min` | высота ряда (default) | 40 px (24 px, если рядов больше 3) |
| `visibility=dense` | тепловая карта: оттенок по значению | — |

Оконные функции — так, как их рисует UCSC: **maximum** показывает значение столбца, самое далёкое
от нуля, **minimum** — самое близкое, **mean** — среднее по основаниям с данными; **mean + whiskers**
рисует среднее тёмным, среднее ± 1 SD средним тоном и крайнее значение светлым. Точка — один
пиксель экрана; пока точек в окне мало (меньше 0,8 × ширины дорожки в пикселях), они 2 × 2 px —
так их легче видеть.

**Если TDF ничего не говорит о том, как его рисовать**: файл типа `ALLELE_FREQUENCY` рисуется
точками; так же — файл, все значения которого лежат в 0–1 в отдельных позициях (покрывают меньше
половины отрезка, на котором лежат, как аллельные доли вариантов), на постоянной шкале 0–1. Всё
остальное — столбиками, как по умолчанию у UCSC. bigWig без настроек рисуется по умолчаниям UCSC
(столбики, maximum, автоматическая шкала).

**Точки из самих значений показывают каждое значение**, даже если в один столбец экрана попало
несколько, поэтому распределение (например, аллельные доли около 0,5 и 1) видно на любом масштабе.
Точки из сводок — по одной на окно, на уровне его значения.

- **Правый клик** по дорожке значений: рисовать столбиками, точками, линией или тепловой картой;
  оконная функция; шкала (авто, 0–1, `viewLimits` из файла); всегда включать ноль; логарифмическая
  шкала; высота ряда. Выбор запоминается для этого файла в этом браузере; **Вернуть настройки
  файла** его забывает.
- **Клик** по ряду — карточка: имя дорожки и значение в этой позиции (ближайшее значение в пределах
  нескольких пикселей), а для столбца экрана с несколькими значениями или сводки — также их среднее,
  минимум, максимум и число оснований с данными.
- В строке имени — шкала однорядного файла (`0–1`); если рядов несколько, у каждого своя.
- Имена контигов совпадают с `chr` и без, как везде в LGV.

## 8. Покрытие

У каждого образца есть дорожка покрытия: серые столбики глубины, шкала в углу (`0–31×`). Где
не-референсные основания составляют от 20% ридов (**Вид → Подсвечивать аллели от**), столбик
раскрашен по основаниям.

- **Риды загружаются в окнах до 200 кб** (Вид → Грузить риды до, 1–1000 кб). Загружаемое окно
  чуть шире экрана. В более широком окне читается только глубина (быстро, без цветов аллелей),
  область ридов объясняет почему, а сообщение внизу предлагает **Загрузить риды** и называет,
  сколько ридов ожидать, и — если каждый файл уже читался — ожидаемое время (по тому, как быстро
  этот файл читался до сих пор); после этого окна на этом контиге до 1,5 раза шире загружают риды
  без вопроса. Сколько ридов придёт, предсказуемо: глубина × окно ÷ длина рида, а с даунсэмплингом
  не больше «ридов на окно» × окно ÷ ширина окна даунсэмплинга.
- Покрытие считает **все** риды, прошедшие фильтры, в том числе там, где показанные риды
  проредены даунсэмплингом.
- При ширине окна больше 1 Мб считается только глубина (без цветных аллелей): так загрузка в
  несколько раз быстрее, а аллели на таком масштабе всё равно не видны. Риды в таких окнах не
  читаются вовсе (меньше пикселя каждый, а миллион ридов экзома читался бы, передавался и
  раскладывался минутами); на месте ридов — подсказка приблизиться. То же, если в окне больше
  300 000 ридов. Если, пока читается широкое окно, вы приблизились, чтение широкого окна
  останавливается и новый вид не ждёт его. Широкое окно читается частями сразу несколькими
  фоновыми потоками браузера, а покрытие хранится как наибольшая глубина в коротких интервалах
  (16–64 п. н.), поэтому перемещение по нему рисуется сразу.
- **Больше 1 Мб покрытие сначала появляется сразу как оценка по индексу** (ничего не читается:
  индекс говорит, сколько байт ридов начинается в каждых 16 кб, а это идёт вместе с глубиной).
  Шкала — `≈ 0–31×`; в глубину она пересчитана по окнам этого файла, уже показанным подробно (до
  этого — в относительных единицах). Это среднее за 16 кб, а не пик. До 10 Мб затем читается точная
  глубина и заменяет оценку; более широкие виды остаются с оценкой. Клик по покрытию по-прежнему
  даёт точный счёт в основании.
- **Клик по покрытию** — счёт по позиции. В верхней строке — позиция, **Copy** и **×**;
  ниже:

  ```
  Total count = 22
  A = 0 (0%, 0+, 0−)
  C (reference) = 12 (55%, 4+, 8−) mQV 37
  G = 10 (45%, 8+, 2−) mQV 34
  T = 0 (0%, 0+, 0−)
  DEL = 0 (0+, 0−)
  INS = 0 (0+, 0−)
  ```

  Для каждого основания: число ридов, доля от всех, риды на прямой (+) и обратной (−) цепи и
  **mQV**. **Total count** — сумма A + C + G + T + N (делеции
  считаются отдельно). **DEL** — риды с делецией в этой позиции. **INS** — риды с инсерцией сразу
  после этого основания. Числа считаются по **всем ридам в позиции**, перечитанным из файла, так
  что даунсэмплинг на них не влияет; фильтры из **Вид** (дубликаты, MAPQ, вторичные, не прошедшие
  QC) действуют, как и для изображения. Посчитанный столбик обведён тонкой серой рамкой.

  **mQV — не общепринятый показатель**, поэтому вот точно, что это такое: среднее качество
  оснований (Phred QV, как записано в файле) данного основания в этой позиции по ридам, где оно
  встретилось: `mQV = (QV₁ + … + QVₙ) / n`, с округлением. Риды без записанного качества в среднее не
  входят (если качества нет ни у одного, mQV не показывается). Помогает отличить настоящий аллель,
  который обычно прочитан с таким же качеством, как референсное основание, от скопления ошибок
  секвенирования с низким качеством. Это среднее арифметическое значений Phred, а не вероятностей
  ошибки, поэтому несколько очень плохих оснований тянут его вниз слабее, чем среднюю частоту
  ошибок. При наведении на строку карточки эти пояснения видны кратко.

## 9. Риды: как они нарисованы

- **Тело рида**: серое по умолчанию или раскрашено (правый клик → Раскраска): по цепи; по
  ориентации пары и размеру инсерта (красный — инсерт больше ожидаемого, синий — меньше, зелёный —
  RF, бирюзовый — FF или RR, оранжевый — мейт не выровнен, свой цвет для каждой хромосомы, если мейт
  на другой; ожидаемый размер — диапазон 0,5–99,5% загруженных пар); по значению тега (например,
  `HP` для гаплотипов).
- **Цепь**: 3′-конец каждого рида заострён, поэтому направление видно при любой
  раскраске.
- **MAPQ**: тело рида с низким качеством картирования прозрачно (50% при MAPQ 0, всё меньше до
  сплошного при MAPQ 40 и выше; настраивается вплоть до 100% — пустой рид): цвет рида поверх фона,
  никогда не светлее фона. У каждого рида при любом MAPQ один и тот же тонкий бледно-серый контур,
  поэтому бледный или пустой рид виден и при отдалении. Несовпадения, инсерции и отметки клипов не
  бледнеют: их цвет зависит только от качества основания.
- **Несовпадения**: раскрашены только основания, отличные от референса: A — зелёный, C — синий,
  G — оранжевый, T — красный; N не отмечается. Буквы внутри ридов видны с 7 пикселей на основание
  при высоте ряда от 9 пикселей.
- **Качество основания**: ниже Q5 несовпадение рисуется на 20%, к Q20 — в полную силу (выключается:
  Вид → затенять основания низкого качества).
- **При отдалении** одиночные несовпадения бледнеют, чтобы ошибки секвенирования не рябили; позиции,
  где не-референсное основание проходит порог аллеля, остаются яркими.
- **Инсерции** — фиолетовая черта, длина подписана сверху с 10 пикселей на основание. **Клик по
  черте** (в пределах нескольких пикселей) — карточка инсерции: место между двумя основаниями
  (`chr1:21,001^21,002`), длина, вставленные основания, их качество и имя рида; черта обведена.
  **Copy** копирует вставленные основания в FASTA: `>имя/2_insertion_chr1:21001^21002`. **Делеции** —
  тёмная линия. **Сплайс-разрывы (N)** — тонкая серая линия.
- **Soft clip** (показаны по умолчанию; правый клик → Показывать soft clip): клипированные основания
  продолжают рид его цветом, чуть ниже по высоте, чтобы была видна граница клипа; отличные от
  референса раскрашены как несовпадения. Если клипы скрыты, место клипа отмечено розовой чертой.
- **Пары** (правый клик → Показывать парами): оба мейта в одном ряду, соединены тонкой серой линией (одного цвета при любом цвете ридов и MAPQ);
  перекрытие мейтов затенено. Если мейт вне загруженного участка, линия идёт туда, где он лежит.
- **Даунсэмплинг**: в глубоких регионах остаётся не больше 100 ридов на окно 50 п.н. (настраивается); метки над ридами показывают, где риды пропущены. Покрытие при этом считает все риды. Какие риды остаются, решается по их именам, поэтому при каждой загрузке одинаково, и **пары не разрываются**: если рид оставлен, его мейт в загруженном участке тоже остаётся (окно может тогда содержать до вдвое больше ридов). Мейт, открытый из карточки (**К мейту**, **Мейт в соседнем окне**), показывается всегда.
- **Ряды** не перетасовываются сами: при сдвиге, перезагрузке или смене раскраски каждый рид
  остаётся в своём ряду. Новая раскладка — только при смене группировки, сортировки, фильтров или
  даунсэмплинга.

## 10. Карточка рида

**Клик по риду** — карточка: имя, образец, read group, длина, флаги;
картирование (основное, вторичное или дополнительное, MAPQ), участок референса и цепь, CIGAR,
клипы; мейт (выровнен ли, начало, размер инсерта, первый или второй, ориентация пары); все теги (RG
используется для образца и указан как скрытый). Внизу — **Location** и **Base** в точке клика с
качеством, например `Base = C @ QV 37 (soft-clipped)`.

- **Read / Read and mate** наверху — один рид или оба мейта рядом (мейт показывается, если загружен
  в любом окне). Когда показаны оба, у каждого мейта, покрывающего точку клика, свои Location /
  Base: на экране у наложенных мейтов видна только одна буква.
- Основание, о котором карточка, **обведено** тонкой линией в риде (и в мейте).
- **Go to mate** — перейти к мейту (если мейт в загруженном участке, но не показан из-за даунсэмплинга,
  карточка так и пишет, а обе кнопки его покажут); **Mate in split screen** — открыть его в новом окне; **Copy** —
  скопировать текст.
- **×** вверху справа закрывает карточку (и Escape).
- **Карточку можно тащить за верхнюю строку**; следующие карточки открываются там, где вы её
  оставили (пока страница открыта), даже если она видна не целиком.

## 11. Меню по правому клику

Правый клик по ридам:

- **Показать регион мейта в соседнем окне** (у парного рида с выровненным мейтом).
- **Копировать последовательность рида**, **Копировать реверс-комплемент рида**, **Копировать
  левый / правый soft clip**, **Копировать пару ридов (FASTA)**. Всё копируется в формате FASTA с
  именем рида: `>имя/1`; реверс-комплемент — `>имя/1_revcomp`; клипы — `>имя/1_left_clip` и
  `>имя/1_right_clip`; пара — `>имя/1` и `>имя/2`. Последовательность — как в файле, по прямой цепи
  референса (реверс-комплемент — противоположная цепь, от 5′ к 3′). Неподходящие пункты неактивны.
- **Показывать парами**, **Показывать soft clip**.
- **Раскраска**: нет, цепь, ориентация пары и размер инсерта, значение тега (с полем тега).
- **Сортировка** в точке клика: по началу (без сортировки), по основанию, MAPQ, цепи, размеру
  инсерта. Риды, покрывающие эту позицию, поднимаются наверх в этом порядке. **S** — сортировка по
  основанию в центре экрана.

## 12. Несколько образцов

Каждый открытый образец — дорожка под общей линейкой, в той же позиции. У каждого своё покрытие,
риды и прокрутка. Если образцы не помещаются, каждый сохраняет минимальную высоту (**Вид →
Минимальная высота образца**, по умолчанию 240 пикселей), а вся стопка прокручивается под
закреплёнными линейкой и дорожкой генов:

- колесо над ридами образца листает его ряды, а когда они кончились — всю стопку;
- колесо или перетаскивание по вертикали над покрытием — вся стопка;
- полоса прокрутки справа, в своей полосе (окна заканчиваются до неё, под ней ничего не прячется);
  PageUp / PageDown.

## 13. Настройки вида

**Вид** открывает настройки; они хранятся в браузере как **профиль отображения**, который можно
скопировать как JSON, вставить чужой и применить или сбросить.

- **Риды**: высота рида (1–24 пикселя), раскраска, тег для раскраски, затенение оснований низкого
  качества, показ soft clip, прозрачность по MAPQ (от / до MQ, прозрачность при низком MQ: 0% — сплошной рид, 100% —
  пустой, только контур; так на любом масштабе: у рида уже 3 пикселей остаются верхняя и нижняя
  линии). У каждого рида тонкий бледно-серый контур; заострённый 3′-конец рисуется в
  видах до 5 кб, дальше риды — прямоугольники. Несовпадения, инсерции и клипы от MAPQ не бледнеют:
  их цвет зависит только от качества самого основания.
- **Группировка и сортировка**: по цепи, первому / второму в паре, ориентации пары или тегу;
  сортировка рядов.
- **Фильтры**: окно ридов (грузить риды до, кб, см. раздел 8); минимальный MAPQ; скрыть дубликаты, вторичные, дополнительные, не прошедшие QC;
  даунсэмплинг (ридов на окно, размер окна). Фильтры и даунсэмплинг работают при чтении, поэтому
  их смена перечитывает участок.
- **Покрытие**: минимальная высота образца, высота дорожки покрытия, порог подсветки аллелей.
- **Экран**: язык, скрыть верхнюю панель, дорожка генов, что открывать при запуске.

## 15. Сообщения и ограничения

- Если участок потребует прочитать больше 64 МБ сжатых данных по ссылке или 512 МБ с диска
  (с диска читается намного быстрее), LGV сначала спросит, указав размер; кнопка загрузки читает
  его. После этого тот же контиг в этом окне не спрашивается снова для участков до 1,5 раза больше.
  С длинными ридами (nanopore, PacBio) любой участок короткого контига, например плазмиды, требует
  примерно тех же данных, потому что риды покрывают его целиком: от приближения размер не
  уменьшается.
- Перекрывающиеся длинные риды складываются в тысячи рядов; к рисованию готовятся только ряды около
  видимых, остальные — по мере прокрутки к ним.
- Повреждённый файл даёт понятное сообщение о том, что не так (например, не совпала контрольная
  сумма блока), вместо показа неверных данных.
- Чтение дольше 60 секунд останавливается с сообщением; возможно, файл повреждён. Каждый образец
  читается по одному запросу за раз, и ждёт только самый новый вид каждого окна, поэтому быстрые
  сдвиги и масштабирование не копят очередь чтений.
- **О программе → Скопировать журнал диагностики** копирует, что занимало время в этом сеансе (чтение
  образцов со временем, медленные кадры, занятость страницы, перезапуски фонового чтения): пришлите
  его вместе с описанием зависания или медленного шага. Журнал хранится только в странице; в нём
  имена файлов и локусы, ридов нет.
- Сообщения внизу закрываются крестиком или кликом; короткие исчезают сами.
- **Не найден индекс**: выберите индекс вместе с файлом, всю папку или разрешите папку, когда LGV
  спросит (3.1).
- **Другая сборка генома**: образец выровнен на другой референс, чем загруженный (3.3).

## 15a. Картинки и ссылки

- **PNG** сохраняет вид как на экране — все окна, карту хромосомы, гены, дорожки, покрытие и риды —
  в разрешении экрана, со строкой внизу: локусы, образцы, референс и дата. Имя файла — по первому
  локусу, например `LGV_chr7_117559500-117560000.png`. Карточки и меню в картинку не попадают.
- **Ссылка** копирует ссылку, открывающую этот вид: референс, образцы и дорожки, открытые по
  ссылкам, и локусы всех окон. Файлы с этого компьютера в ссылку попасть не могут (сообщение их
  называет), токены доступа в ссылку не кладутся никогда.
- **Открытие LGV из другой системы** (LIMS, отчёт, таблица вариантов): добавьте параметры после `#`
  (или `?`) к адресу `lgv.html`:

  ```
  lgv.html#ref=hg38&file=https://server/sample.cram&locus=CFTR
  ```

  - `ref` — `hg38`, `hg19`, `chm13`, `demo` или ссылка на FASTA (`.fai` рядом, `.gzi` для `.fa.gz`);
    без него — референс из «Вид → При запуске открывать»;
  - `file` — ссылка на BAM, CRAM или дорожку аннотации; для нескольких — повторить;
  - `index` — ссылки на индексы BAM / CRAM в том же порядке, если они лежат не рядом с файлами;
  - `locus` — локусы или гены; несколько через пробел (`%20` или `+`) открываются рядом.

  Читаются только `https`-ссылки (и `http` на этом компьютере). Параметры после `#` остаются в
  браузере и не отправляются на сервер, где лежит `lgv.html`, поэтому для данных пациентов лучше
  они.

## 16. Конфиденциальность и безопасность

- Данные идут только между выбранными вами файлами или ссылками и вашим компьютером. LGV ничего
  никуда не отправляет; единственное соединение, которое он делает сам, — загрузка референса,
  выбранного для открытия при запуске (только последовательность).
- Поиск генов и дорожка генов встроены: введённые названия генов никуда не отправляются.
- В браузере сохраняется только профиль отображения. Токены, ссылки и доступ к папкам не
  сохраняются никогда.
- Каждый файл считается недоверенным: повреждённый или враждебный файл заканчивается понятным
  сообщением, а не неверными данными, зависанием или падением. Подробности — в
  [SECURITY.md](../SECURITY.md).
